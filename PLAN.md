## Що це

Окремий GUI-лаунчер для щоденного запуску Codex CLI з профілем `umod`.
Не установник — припускає, що UMOD уже налаштований через UMOD-Installer
(`~/.codex/config.toml`, credential-файл у `~/.umod/`).

Вікно: вибрав модель, натиснув «Запустити» — відкрився Codex.

## Що лишилось

Пункти йдуть у порядку виконання. Пункт 1 — перший, бо решта правок лягає на
код, який ніхто ще не бачив у роботі: спершу треба переконатись, що поточне
дерево взагалі збирається і запускається.

Після кожного пункту: `cargo build --release --offline`, запуск exe, окремий
коміт. Не збирати кілька пунктів в один коміт — якщо щось зламається, буде
незрозуміло що саме.

Граф коду проєкту проіндексований (`codebase-memory`, проєкт
`umod-codex-gui`, 61 вузол): замість Grep по теці — `search_graph`,
`search_code`, `trace_path`. Після правок — переіндексувати.

### 1. Перевірити, що поточний код узагалі збирається

`target/release/umod-codex-gui.exe` датований 18:32, а правки `57fbdba`
лягли пізніше. Тобто зібраний **не той** код, що зараз у `main`.

- [ ] `cargo build --release --offline` на поточному дереві
- [ ] Запустити exe і пройти сценарій: пуск проксі → статус зелений →
      «Запустити Codex» → сесія Codex працює → «Стоп» → статус червоний

Це перше. Решта пунктів — про код, якого ще ніхто не бачив у роботі.

### 2. `Cargo.lock` — у git

Єдиний пункт аудиту, який не виконали. При збірці з vendor це не косметика:
без lock граф залежностей перерішується, і vendor перестає збігатися.

- [ ] Прибрати рядок `Cargo.lock` з `.gitignore`
- [ ] `git add -f Cargo.lock` і закомітити

### 3. HTTP-проба не має запускати PowerShell

`src/proxy.rs:27` робить пробу так: `Command::new("powershell")` з
`Invoke-WebRequest`. Два наслідки, обидва видимі користувачу:

- **Вікна консолі.** Бінарник зібраний із `windows_subsystem = "windows"`,
  тож власної консолі в нього немає — і кожен запуск `powershell.exe`
  малює чорне вікно. `is_listening` викликається в циклі очікування
  (`src/proxy.rs:188`) кожні 500 мс до 40 разів: до сорока спалахів консолі
  на один старт проксі.
- **Вартість.** Запуск PowerShell — 200–400 мс на пробу, тобто цикл
  очікування витрачає більше часу на себе, ніж на проксі.

Проба — це один рядок `GET /v1/models HTTP/1.1` у сокет, який функція вже
відкрила рядком вище. Ніяких залежностей і жодного стороннього процесу.

- [ ] Переписати `is_listening` на прямий HTTP-запит через `TcpStream`
- [ ] Читати перший рядок відповіді: `200`, `401`, `403` — проксі живий
- [ ] Тим часом (якщо проба лишається зовнішньою) — `CREATE_NO_WINDOW`
      (`0x08000000`) через `std::os::windows::process::CommandExt`
- [ ] Те саме для діалогу вибору файлу `rfd_file_dialog` — він теж кличе
      PowerShell і теж блимне вікном

### 4. Порт: env більше не читається

Після прибирання поля порт зашитий числом у двох місцях —
`src/main.rs:137` і `src/main.rs:192`. Установник же документує
`UMOD_PROXY_PORT`, і `Umod-Codex.ps1` його поважає. Якщо проксі піднято
на іншому порту, GUI його не побачить і спробує підняти другий.

- [ ] Одна константа замість двох літералів
- [ ] Читати `UMOD_PROXY_PORT` при старті, з 8787 за замовчуванням
- [ ] Якщо порт узятий з env і не збігається з `base_url` у
      `~/.codex/config.toml` — сказати про це в журналі, а не мовчати

### 5. Дрібне, але видиме

- [ ] `now_str` — це `UTC + 3` жорстко. Влітку збігається, з кінця жовтня
      журнал бреше на годину. Або брати локальний час у системи, або
      прибрати години і лишити відносний час
- [ ] `addr.parse().unwrap()` у `is_listening` — паніка на кривому порту
- [ ] Іконка: `.ico` сама в exe не потрапить, потрібен `embed-resource`
      або rc. Це нова залежність у vendor — перевірити, чи є вона там
- [ ] Збереження вибраної моделі й credential між запусками (JSON у
      `%APPDATA%`). Для щоденного лаунчера це найдешевша корисна річ

### 6. Тести

`#[cfg(test)]` у проєкті немає жодного.

- [ ] `find_credential` на тимчасовій теці: нуль файлів, один, два
      (третій випадок — той, що давав мовчазну відмову)
- [ ] Розбір відповіді проби: `200/401/403` → живий, решта → ні

### 7. macOS

- [ ] Перевірити збірку egui під macOS
- [ ] `codex.rs` — гілка `open -a Terminal` написана, не тестована
- [ ] `find_python` через `where` — Windows-only, під Unix потрібна гілка
- [ ] `.app` packaging, `.icns`

## Довідка: як Codex знаходить проксі

З `config.toml` установника:

```toml
[model_providers.umod]
base_url = "http://127.0.0.1:8787/v1"
env_key  = "UMOD_PROXY_KEY"
wire_api = "responses"
```

1. **Codex не має прапорця `--port`.** Адреса проксі — лише з `config.toml`.
2. **Порт у GUI керує тільки проксі.** Через це поле порту й прибрали:
   проксі на 8888 при `base_url` 8787 дає зелений індикатор і мертвий Codex.
3. `UMOD_PROXY_KEY` — placeholder, не секрет. Проксі прибирає `Authorization`
   від клієнта і підставляє справжній Entra-токен.
4. Проба саме `/v1/models` з будь-яким Bearer: 401/403 доводить, що слухає
   проксі, а не чужий процес на порту. Так зроблено і в `Umod-Codex.ps1`
   установника («Probe the PORT, not the process»).

## Довідка: середовище і збірка

**ESET блокує мережу всім Windows-процесам** — `powershell.exe`, `pwsh.exe`,
`git.exe`, `curl.exe`, `cargo.exe`. Відмова за 3–24 мс. Мережа є тільки у
WSL2. Тому vendor збирали в обхід, циклом `build_loop*.ps1`.

Цикл спрацював — але він одноразовий: він відновлює vendor лише з поточного
стану помилок `cargo`. Для відтворюваності потрібне те, чого досі немає:
`Cargo.lock` у git (пункт 2). Якщо колись знадобиться зібрати vendor з нуля
на іншій машині — один `cargo vendor` у WSL зробить те саме без 300 ітерацій:

```
wsl bash -lc "cd /mnt/c/Users/Гартунг/Desktop/umod-codex-gui && cargo vendor vendor"
```

Відоме місце ручної правки: `vendor/egui-winit-0.36.2/Cargo.toml` — прибрано
`smithay-clipboard` з feature `clipboard` (Linux-only). Плюс `fix_objc.ps1`.

## Безпека

- `UMOD_PROXY_KEY` — placeholder, не секрет; проксі підставляє справжній токен
- Credential-файл — єдиний секрет; GUI показує лише шлях, не вміст
- Проксі слухає лише `127.0.0.1`: він додає `Authorization` до всього, що
  пересилає, тож слухач на `0.0.0.0` був би відкритим проксі в платформу
- `.env` і `**/.umod/` — у `.gitignore`
- Бінарник не потребує прав адміністратора

## Критерій готовності

1. `cargo build --release --offline` проходить на **поточному** дереві
2. GUI запускається без спалахів консольних вікон
3. Індикатор показує реальний стан проксі й міняється після «Пуск» і «Стоп»
4. «Запустити Codex» відкриває робочу сесію Codex на моделі зі списку
5. Кривий credential або зайнятий порт дають **повідомлення в журналі**, а не
   мовчазний відкат до значення за замовчуванням
6. `Cargo.lock` у git — інакше збірка невідтворювана
