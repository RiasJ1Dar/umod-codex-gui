# UMOD Codex GUI — план проєкту (Rust)

## Що це

Окремий GUI-лаунчер для щоденного запуску Codex CLI з профілем `umod`.
Не установник — припускає, що UMOD уже налаштований (через UMOD-Installer).
Вікно: вибрав модель, натиснув «Запустити» — відкрився Codex.

---

## Технологія

**Мова:** Rust 1.97.1 (встановлено)

**GUI-фреймворк:** два варіанти (див. нижче)

**Цільові платформи:** Windows (першочергово), macOS (пізніше)

---

## Варіант A: egui / eframe (рекомендовано)

- Сучасний, крос-платформний, immediate-mode GUI
- Один бінарник, без системних залежностей
- Розмір ~10–15 МБ після компіляції
- Потребує завантаження крейтів (egui, eframe, wgpu, winit)
- **Зараз не можна скомпілювати** — немає мережі до crates.io

### План egui
1. Написати `Cargo.toml` + `src/main.rs` (повний код)
2. Написати інструкцію зі збірки
3. Компіляція на машині з мережею:
   ```bash
   cd umod-codex-gui
   cargo build --release
   ```
4. Готовий `.exe` (~15 МБ)

---

## Варіант B: windows-sys (Win32 API) — можна скомпілювати ЗАРАЗ

- Крейт `windows-sys` вже в кеші (0.61.2)
- Має `Win32_UI_WindowsAndMessaging`, `Win32_Graphics_Gdi`
- Нативний Win32 GUI: вікно, кнопки, поля, список
- Розмір ~1–2 МБ
- Тільки Windows (macOS потребує окремого коду)

### План windows-sys
1. `Cargo.toml` з `windows-sys` features (Win32_UI, Win32_Graphics)
2. `src/main.rs` — Win32 window procedure
3. Елементи: вікно, випадаючий список (моделі), поле (credential), кнопки
4. Компіляція: `cargo build --release` (offline, `--offline`)
5. Готовий `.exe` (~1–2 МБ)

## Функції GUI

```
┌─────────────────────────────────────────────────────┐
│  UMOD Codex                                          │
│                                                     │
│  Модель:     [ glm-5.2                    ▼]        │
│  Credential: [C:\Users\...\.umod\a5081.env] [Огляд…] │
│  Порт проксі:[ 8787          ]                       │
│                                                     │
│  Статус проксі: ● працює на 127.0.0.1:8787          │
│                                                     │
│  [ ▶ Запустити Codex ]  [ ⟳ Пуск проксі ]  [ ⬹ ]   │
│                                                     │
│  ┌─ Журнал ──────────────────────────────────────┐  │
│  │ [14:30] Проксі запущено                       │  │
│  │ [14:30] Модель: glm-5.2                       │  │
│  │ [14:31] Codex запущено з профілем umod       │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

1. **Вибір моделі** — випадаючий список:
   - glm-5.2 (за замовчуванням)
   - gpt-5.6-sol / terra / luna
   - deepseek-v4.1-flash
2. **Вибір credential** — поле + кнопка «Огляд…» (автозаповнення)
3. **Порт проксі** — за замовчуванням 8787
4. **Статус проксі** — індикатор + текст
5. **Кнопка «Запустити Codex»** — стартує проксі (за потреби) + Codex
6. **Кнопка «Пуск проксі»** — лише проксі
7. **Кнопка «Стоп проксі»** — зупиняє проксі
8. **Журнал** — текстове поле з подіями

## Логіка запуску

```
Користувач → «Запустити Codex»
   ↓
Перевірити порт 8787 → проксі працює?
   ↓ ні
Запустити python umod-token-proxy (фоновий процес)
   ↓
Дочекатися відповіді з порту 8787 (до 20 с)
   ↓
Запустити codex --profile umod --model <вибрана>
   ↓ (у новому вікні Terminal/Console)
Codex працює
```

## Безпека

- `UMOD_PROXY_KEY` — placeholder, не секрет
- Credential-файл — єдиний секрет, GUI не показує вміст
- Проксі слухає лише 127.0.0.1
- Нічого не качається з мережі
- Бінарник не потребує прав адміністратора
